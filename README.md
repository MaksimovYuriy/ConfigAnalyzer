# ConfigAnalyzer

Утилита на Go для поиска небезопасных настроек в YAML и JSON.

Проект находится на этапе подготовки структуры: анализ конфигураций ещё не
реализован. Сейчас доступна справка; остальные вызовы завершаются с кодом `2`.

## Запуск

Нужна версия Go, указанная в `go.mod` (также закреплена в `.tool-versions`).

```sh
go run ./cmd/config-analyzer --help
```

Сборка:

```sh
mkdir -p bin
go build -o bin/config-analyzer ./cmd/config-analyzer
```

## Структура

- `cmd/config-analyzer` — точка входа приложения.
- `internal/cli` — аргументы, вывод и коды завершения CLI.
- `pkg/config` — публичный парсер YAML и JSON без заданной схемы.
- `internal/analyzer` — модель проблемы и общий анализатор.
- `internal/rules` — правила проверки и варианты названий параметров.
- `.github/workflows/ci.yml` — форматирование, vet, тесты и сборка.

## Проверка

## Парсер

`config.Parse(io.Reader)` возвращает документ с определённым форматом (`json`
или `yaml`) и корневым `yaml.Node`. Такое представление сохраняет теги (включая
Ansible `!vault`), порядок полей и позиции в исходном документе.

Сначала проверяется валидность JSON; иначе ввод разбирается как YAML. Поэтому
невалидный JSON, допустимый в YAML, принимается как YAML. Разрешён любой тип
корня, в том числе число `5`, строка, массив и `null`. Пустой ввод, повторяющиеся
скалярные ключи, рекурсивные алиасы и несколько документов в одном потоке приводят
к ошибке. Парсер не закрывает переданный поток.

```go
import "github.com/MaksimovYuriy/ConfigAnalyzer/pkg/config"

doc, err := config.Parse(reader)
if err != nil {
    return err
}
// doc.Format — обнаруженный формат, doc.Root — дерево конфигурации.
```
